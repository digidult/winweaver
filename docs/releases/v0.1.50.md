# WinWeaver 0.1.50

WinWeaver in a browser (winweaverweb) after its first look (the list of 10.11.2026).

## What changed

- **No dead buttons**: what needs this PC or its disk is left out of the menus, the command bars
  and the panels of a browser: the links and the buttons Open in the registry of the description
  of a rule, of a catalog in its editor, of a registry file and of a Group Policy file; Apply to
  this PC of a registry file; Create on this PC and Apply passwords of a users file; Read again
  and the Group Policy files of this Windows; the import of the templates of this Windows or of a
  folder; Open of a theme; the section Files of the settings. The choice of the renderer leaves
  the settings of a page with W# 0.1.50.
- **The menu Scripts**: This PC is named Scripts in a browser, where it holds the scripts, the
  registry files and the audit report alone; the parts of the description are Scripts, this rule
  and Scripts, this selection.
- **A catalog opened is imported**: a catalog file or an archive of policy templates opened in a
  browser is loaded at once, its options in the profiles, as WinWeaver loads the catalogs next to
  it, and the page keeps it for the next visit while its storage has room. Before, it opened in a
  tab only.
- **The editor of a catalog saves**: Save downloads the catalog file and keeps an import in the
  page, its options changed at once. Before, it wrote into the storage of the page alone, or
  failed there.
- **Compare with a file works in a browser**, and so do the accounts of a users file for a
  profile, Add a file of a Group Policy file, Open a Group Policy file, Import a catalog file or
  an archive and Open an audit report: they ask the dialog of the page, whose file comes later.
  An audit report also opens with Open.
- An import saved, a new catalog and the removal of an import go through the file layer: in a
  browser the storage of the page, where the folder of the import made with `std::fs` failed.
