# WinWeaver 0.26.0

The customer's list of 25.10.2026: the command line, the catalogs, the Group Policy editor, the
window, and wwlite without the code of the full edition.

## What is new

- The command line writes the answer file of a profile (`--build`), imports policy templates (the
  templates of this Windows, a folder, an ADMX file, an archive or a catalog file: `--import-admx`),
  exports a catalog file (`--export-catalog`), reads this PC into a new profile or its answer file
  (`--read-pc`) and compares two profiles into a `.wwdiff` (`--diff`). `--out` of every command names
  the file when it ends with the extension the command writes, else the folder for the default name.
- The MCP tab has Open and Save as in its bar.
- Compare of a catalog opens a tab: the policies that differ in the tree of their categories, with
  switches for the ones only in the first catalog, only in the second and the different ones, the
  selected policy as it is in both catalogs side by side; Save the report writes a Markdown file, As a
  page shows it.
- The work in the background (a read of this PC, an import of policy templates, a change of this PC,
  a search of the registry) shows in a panel in the lower right corner with the time it has taken and
  Stop where it can stop; the panel folds to a spinner.
- A Group Policy file (`Registry.pol`) is edited in its tab: entries made, changed and removed, the
  root of a file outside Group Policy chosen in the bar, the entries of another `.pol` file or the
  changes of a `.reg` file added, the file saved in the format of Group Policy (the files of this
  Windows as copies elsewhere) or as a registry file; unsaved changes come back from a draft.
- Copy to in the bar of a catalog tab copies the selected policy or group into a catalog open in its
  editor, or into a new catalog: a catalog of only the policies needed, to pass on as a file.
- Only on in the bar of a profile shows the rules that are on with their groups open; the MCP tools
  `list_groups`, `list_rules` and `search_rules` take `only_on`.
- When the tabs are wider than the window, the tab row scrolls with the wheel, the active tab comes
  into view, and a button lists every tab.
- The catalog is arranged by mechanism: Installation holds what the answer file and its scripts do,
  the root Policies (named so now) every rule that only writes the registry, Other the services,
  features, apps, programs and scripts on a running Windows. No rule id changed.
- Every item of a menu has an icon; Build has a hammer.
- wwlite is built without the code of the full edition (the feature `full` of the window library):
  nothing of This PC, the registry, registry and Group Policy files, users files, the catalogs,
  diffs, bookmarks and MCP is in its executable.
- The fields of the parameters of a rule take the width of the panel; the support contacts and the
  autologon account have the limits of the answer file, counted as you type.

## Fixes and changes inside

- The clocks of W# come from `web-time`, so a build for the browser can go on.
- `winweaver-win` is a dependency of Windows alone; users files are a feature of the core and of the
  Windows crate.
- CI checks, tests and builds wwlite alone, since cargo unifies the features of one build.
