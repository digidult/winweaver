# WinWeaver 0.1.51

The findings of the audit of 11.11.2026 (security and quality), fixed. No file format changed.

## What changed

- **No secret leaves through MCP**: `preview_build` hides the product key and the passwords of
  the whole answer file and cuts it after; before, it cut first, and a cut inside a secret
  showed its beginning. `compare_profiles` says of the product key only whether each profile has
  one; before, it returned both keys.
- **A control character never reaches the answer file**: a line break or another control
  character in a text that is written into it (the time zone, an account, a text parameter of a
  rule in effect) is an error of the check, and the build refuses it. Windows Setup refuses such
  a file whole. A tab stays in a password, a display name, a description and a text parameter.
- **A profile named like a slot is a name**: the templates are filled in one pass, so a profile
  named `{{blocks}}` no longer takes the place of the blocks of a script.
- **A line of a script is never filled**: the lines of a `ps` action and the commands of the
  answer file are written as the catalog has them, and the check of the catalog refuses a
  parameter in them (no rule had one). A value of a profile reaches a script only quoted.
- **The installation media is never the drive of Windows on a running PC**: Apply to this PC and
  the stand-alone apply script look for `sources\sxs` and `Drivers` on the other drives only, so
  a folder a standard user made on `C:` is never installed by an administrator. The answer file
  (the installation itself) looks at every drive as before.
- **The folder of a profile of a users file is new or empty**: Create on this PC and the script
  refuse a folder that holds something, a link, a file and the root of a drive, with the reason;
  before, the folder was taken over (its access list replaced, its owner changed). The check of a
  users file names a profile path that is the root of a drive. A profile an account has in that
  folder already is left as it is.
- **The iterations of a users file have an upper limit** (10 000 000), in the program and in the
  script: a file that asks for more is refused with the reason, before any key is derived.
- **A Group Policy file with a line break in a key or a name is refused**, and its export as a
  registry file writes every comment as one line: a name could no longer add lines of its own to
  the `.reg` file.
- **A registry file with a long value opens at once**: a value of many continuation lines is
  read in linear time (it was quadratic).
- **Passwords are wiped where they were left**: a password that is replaced, the texts of the
  two password windows, and the part of a users file read before an error.
- **The helper asks Windows for the system folder** (`GetSystemDirectoryW`) and no longer reads
  it from the environment.
- **The messages of the check are translated**, in the eight languages, with the line of its
  counts; so are the status lines of a read of this PC and of an audit report and the messages
  of a check on this PC. The test of the translations now reads the messages of the check and
  finds a text written on the line after its bracket.
- **WinWeaver in a browser**: the list of the imports shows the names and the sizes of its
  catalog files, and Load catalogs finds them (they were read with `std::fs`, which a browser
  has not).
- **CI**: the token of a run only reads the repository (the job `release` alone writes), and
  the downloaded wasm-bindgen is checked against the SHA-256 of its release, as `build-all.cmd`
  checks it.
- Texts brought in line with the code: the comment of the nonce of a plan, the four archives of
  `build-all.cmd`, the rule of the versions, the characters of a rule id.

## Left for a decision

The passwords a `.wwdiff` holds, a MAC over the account list of a users file, what the modes of
the MCP tools mean once an option is on, and the names of the backup and the report of the
helper are not changed here.
