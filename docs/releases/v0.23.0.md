# WinWeaver 0.23.0

A release of structure, not of features: the code was refactored after the customer read it on
21.10.2026 (`docs/refactoring.md`). Nothing installs: unzip and run `winweaver.exe` on Windows 10 or 11.
Changes of a computer belong in a virtual machine or on a test PC first.

The window, the answer file, the scripts, the MCP tools and the file formats do what 0.22.1 did.
Every test of 0.22.1 passes, moved into the new files, not changed.

## What changed on purpose

- The MCP tool `set_group` skips the imported policies when it turns a group on, as the window did
  already (turning a group on never turns on a policy of a template).
- An argument `null` of an MCP tool counts as absent for every tool, as the helpers of the server
  treated it; five tools read it as present before.
- A DWORD or QWORD value with a fraction (`1.5`) is refused by the check of a profile and by the
  scripts instead of being cut to its whole part.
- The errors of the Windows API (the accounts, the groups, the rights of keys) name the text of
  Windows, "access denied" or "the user was not found", instead of the number of the error.
- A button of the command bar that has nothing to do is disabled: Delete in a registry file without
  a removable line, Remove in a users file without a selected account, Open in the registry without
  a selected key.

## Inside

- `winweaver-core`: `admx/`, `render/`, `thispc/` and `registry/` are folders by theme; the four
  JSON documents share the trait `Document` and its errors; the values of actions are read in one
  place (`catalog::values`); the keys of a diff are `diff::ItemKey`.
- `winweaver-win`: the Windows API wrappers live once in `ffi.rs`; the executor of a plan is
  `execute/` (one function per operation, the hive of the default user apart).
- `winweaver-mcp`: the tools are a table (`tools/`), each named once with what it needs; the
  arguments and the errors are typed; the outcome of a call is `Outcome`.
- `winweaver-ui`: the window is `app/` by theme, with the frame drawing every tab by its kind; the
  acts are enums by subsystem and a question over the window is one act; every tab is a document
  that answers the trait `Tab`; the commands of the command bar, the keys and the icons are data
  named once; the shared widgets (the modal window, the side panel, the file dialog in a folder) are
  `widgets.rs`; the views over a thousand lines are folders.
