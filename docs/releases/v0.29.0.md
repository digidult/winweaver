# WinWeaver 0.29.0

The customer's lists of 29.10.2026: three faults, then four changes of the window.

## What is new

- The menu Catalogs loads or unloads a catalog at a click. A setting of General gives the
  other way: the menu lists the loaded catalogs alone and a click opens the tab of one.
- The comparison of two catalogs marks every field of the selected policy on both sides: the
  ones that differ, the ones absent from a side and the ones only in it, with a legend.
- A profile tab shows a disc; the gear belongs to the settings alone.

## Fixed

- A read of this PC into a new profile left out the policies of the loaded templates: only Read
  the selection into this profile read them. The read of the whole PC covers every loaded catalog
  now.
- Users files and renamed accounts. The list of a users file shows the full name beside the name:
  a rename in the Settings or the Control Panel of Windows usually changes only the full name, so
  the list seemed to show the old name; the form says what the name is. A change of the group in
  the form now marks Exactly this group, so the account moves from Administrators to Users (it
  only joined Users before, unless that order was set by hand). The account WinWeaver runs as is
  known by the identifier of its process, not by the name of the session, which stays old after a
  rename until the next sign-in; it stays in Administrators, and the built-in account in use is
  never disabled by an apply.
- Apply to this PC of a registry file named only the first change this PC refused, in the status
  bar, so a file could seem applied when some keys were not written (a key of the computer without
  WinWeaver started as administrator, for example). Every refused change now stands in the message
  bar of the tab, with its key as a link to the registry, and in the log.
- The address row of the registry cut the button Go and the word Key at large text sizes: the
  field takes the width left after the button.
